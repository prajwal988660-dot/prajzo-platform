## 1. Set up the free MongoDB Atlas database (once, about 10 minutes)

The API needs a database address in `apps/api/.env`. Until it has one, `npm run dev` starts the web app, and the API stops with a message saying what's missing.

1. **Sign up** at https://www.mongodb.com/cloud/atlas/register (signing in with Google is fine).
2. **Create a cluster** and pick the **Free** tier:
   - provider: AWS
   - region: **Mumbai (ap-south-1)**, the closest to you
   - cluster name: `prajzo-dev`
3. **Create a database user** when Atlas asks:
   - username: `prajzo-dev`
   - click **Autogenerate Secure Password** and copy the password somewhere safe
4. **Network access:** choose **Add My Current IP Address**.
   - If your internet connection gets a new IP address later, add the new one the same way.
   - The API's log tells you when it can't connect.
5. **Copy the connection string:** in **Connect → Drivers**, copy the string. Atlas offers two forms, and both work:

   ```
   mongodb+srv://<db_username>:<db_password>@prajzo-dev.xxxxx.mongodb.net/?retryWrites=true&w=majority&appName=prajzo-dev
   mongodb://<db_username>:<db_password>@ac-xxxxx-shard-00-00.xxxxx.mongodb.net:27017,…/?ssl=true&replicaSet=atlas-xxxxx-shard-0&authSource=admin
   ```

6. **Fill in the string:**
   - Replace `<db_username>` with your database user's name, removing the `<` and `>` too. The name is shown under **Security → Database Access**, in the **User Name** column.
   - Replace `<db_password>` with that user's password, again removing the `<` and `>`.
   - Add the database name `prajzo` right after `.mongodb.net/` (or after the last `:27017/` in the second form).
   - If the password contains any of `@ : / ? # [ ]`, generate a new one; the autogenerated ones normally don't contain them.
   - When it's done, the string has no `<` or `>` left in it.
7. **Save it:** open `apps/api/.env` and paste the string after `MONGODB_URI=` (no quotes). The file is git-ignored.
   - **Never commit this file, and don't paste the string into chats or issues.**
8. **Check it:**
   - Run `npm run dev`.
   - Open http://localhost:5173/dev/ui.
   - The **API connection** box should say **API ready · database connected**.

`apps/api/.env` already exists on this machine, with a freshly generated `SESSION_SECRET`. On a new machine, copy `apps/api/.env.example` to `apps/api/.env` and fill it in ([ENVIRONMENT.md](ENVIRONMENT.md)).

## 2. Everyday commands

Run these from the repository root (`C:\dev\mine\prajzo`).

| Command | What it does |
|---|---|
| `npm install` | Installs everything for all workspaces (the first run also downloads the MongoDB binary used by tests) |
| `npm run dev` | Starts the web app (http://localhost:5173) and the API (http://localhost:4000) together; both reload when you save a file. Stop with Ctrl+C |
| `npm run check` | Type check, lint, format check, all tests and the production build. Must pass at the end of every phase |
| `npm test` | Only the tests (`npm run test:watch` reruns them as you edit) |
| `npm run format` | Formats the code with Prettier |
| `npm run build` | Production build: `apps/web/dist` and `apps/api/dist/server.js` |

## 3. Create your administrator account (once)

Administrators can't be created on the website; there is no sign-up page for them, on purpose. You create yours in your own terminal:

1. Open a terminal in `C:\dev\mine\prajzo` (in Cursor or VS Code: **Terminal → New Terminal**).
2. Make sure your database connection works (the API connected earlier, and your internet address is allowed in Atlas).
3. Run:

   ```
   npm run admin:create -w @prajzo/api
   ```

4. Answer the questions:
   - **Administrator email address:** the one you'll sign in with (it must not be a customer account's email).
   - **Name:** how you'd like to be addressed.
   - **New password (at least 12 characters):** you won't see anything as you type. That's normal; it is hiding the password. A few random words work well.
   - **Type the password again.**
5. It says `Administrator … has been created`. Sign in at **http://localhost:8080/admin/login** (or http://localhost:5173/admin/login while `npm run dev` runs).

**Forgot the administrator password?** Run the same command with the same email. It asks whether to set a new password. (There is deliberately no emailed reset link for administrators.)

Never type this password into a chat or a file. The command must run in a real terminal window, not through another program.

## 4. Run Prajzo locally like a real server

`npm run dev` is for working on the code. To see Prajzo the way visitors will, as one optimized site served from one address, host it locally:

```
npm run host:local
```

- It builds the site, then starts it in the **background** (no window). It keeps running after you close the terminal or Claude Code, until you stop it or restart the computer.
- It prints the addresses to open:
  - **On this computer:** http://localhost:8080
  - **On your phone**, on the same Wi-Fi or hotspot: the `http://172.x.x.x:8080` style address it prints. That address can change when you reconnect, so run the command again to see the current one.
- **After changing code**, run `npm run host:local` again. It rebuilds and restarts.
- **Stop it** with `npm run host:stop`. It only stops the process that is really listening on port 8080, never an unrelated program.
- **Logs:** `apps/api/logs/local-host.log` explains anything unusual. For example, if the database disconnects, it says why and what to do.
- **Port:** 8080. To use another, set `LOCAL_HOST_PORT` for the command.
- **On shared or public Wi-Fi**, other devices on that network can open the site while it runs. Run `npm run host:stop` when you're done.
- It uses the same database as `npm run dev`: your Atlas database from `apps/api/.env`.

## 5. Troubleshooting

| You see | What to do |
|---|---|
| `The Prajzo API cannot start` followed by `MONGODB_URI is required` or `must be the full connection string` | Do step 1 above. The value must be one line with no spaces, starting with `mongodb+srv://` or `mongodb://` |
| `querySrv ECONNREFUSED` in the API log | Node.js on Windows can't look up `mongodb+srv://` addresses on some PCs, including this one. Keep `DNS_SERVERS=1.1.1.1,8.8.8.8` in `apps/api/.env` (already set here), or use Atlas's `mongodb://` form of the string |
| `Atlas rejected the username or password` | The string still contains `<db_username>` or `<db_password>`, or the password is wrong. Check the user under Security → Database Access; you can set a new password there (Edit → Edit Password) |
| The site says the database is disconnected, or the log says `Atlas did not answer` or `SSL alert number 80` | **Your internet address changed**, and Atlas only lets in addresses it knows. Under Atlas → Network Access, add your current address (**Add IP Address → Add Current IP Address**). You can pick a **temporary** entry that deletes itself after a day or a week. While it is disconnected, the pages still open, but the lists of services and the contact form answer at once with "temporarily unavailable. Please try again in a minute" (the contact form keeps what was typed). The site reconnects by itself within about a minute of the fix; nothing needs restarting. A phone hotspot changes address often, so this will repeat |
| `Database connection failed; retrying in 10s` | The same causes: check Network Access first, then that the password in the string is right. The API keeps retrying, so it reconnects as soon as the setting is fixed |
| "Too many attempts. Please wait a few minutes" when signing in | The sign-in limit (10 failed tries per 15 minutes per connection or email address) was reached. Wait 15 minutes. This protects accounts from password guessing |
| `This command asks you questions … run it yourself in a terminal window` | `admin:create` must run in a real terminal so it can hide the password. Run it from a terminal window, not through another tool |
| Right-click does nothing on http://localhost:8080 | That is the right-click protection (D-037), which production builds have. It is off in `npm run dev`. To turn it off for a build, set `VITE_PROTECT_CONTENT=false` and build again |
| "You've sent a lot of project requests in the last hour" | One customer account sent 10 project requests in an hour (spam protection). Wait an hour, or raise `PROJECT_REQUEST_RATE_LIMIT_MAX` in `apps/api/.env` while testing |
| `Port 8080 is already used by another program` | Something else is using port 8080. Close it, or set `LOCAL_HOST_PORT` to a different number |
| `Port 5173 is already in use` or `Could not start the API on port 4000` | Another copy is already running. Close it, or find it with `Get-NetTCPConnection -LocalPort 5173` |
| The `/dev/ui` page says **API not reachable** | `npm run dev` isn't running, or the API stopped; its message in the terminal says why |

## 6. Password-protect a site (staging)

To keep a copy of Prajzo private, for example on a staging address while you test it, or on your own computer while you show it to someone, give it a password. Every page, CSS and script file, image and API request then asks for a username and password, so people without them can't see or copy anything.

1. Open `apps/api/.env` (on a host, the settings page of your hosting) and add two lines:

   ```
   STAGING_PASSWORD=choose-a-long-password-here
   STAGING_USER=preview
   ```

   The password needs at least 12 characters. The user name is optional (`preview` if you leave it out).

2. Restart the site (`npm run host:local` on your computer).
3. Open the site. The browser asks for the username and password.

To turn the protection off, delete both lines and restart. **Never set it on the live site.** Give the password only to people you want to let in, over a private channel, and change it when they no longer need access.

What this does **not** do: someone who has the password can still use the browser's developer tools and save the page. A password keeps outsiders out; it doesn't stop a person you let in from copying. For that, the Terms say previews and demos stay yours until a project is paid ([D-037](DECISIONS.md)).

`/api/health` stays open without a password, so uptime monitors keep working.

Right-click blocking is separate: it is on in production builds, such as the site on port 8080, and off when you run `npm run dev`. See [ENVIRONMENT.md](ENVIRONMENT.md) for `VITE_PROTECT_CONTENT`.
